## Notes

- Unchanged since `66f31d77`: the scanner gained an onStage progress hook, and this run confirms it is inert — same detections, same verdicts, same timings.
- This is the baseline the manual CI job compares against; it is recorded as
  both Markdown and JSON so `--baseline` has something to read.
- Compared with the previous recorded run on `21e6abb5` (seven repositories,
  60 labelled calls): detection 56/60 → 67/71 and provider identity 43/43 →
  54/54 with llamacoder added, scenarios 15/16 → 17/18, still no false pass or
  false fail. The four unchanged repositories detect exactly what they did.
- **llamacoder is new to the corpus.** Its whole production AI usage goes
  through `together-ai`, which had no recognizer, so before this change every
  one of its calls was only flagged. With the recognizer: 11/11 detected,
  11/11 provider identity, both scenarios correct. Its labels are not blind —
  see `labels_note` in `repos/llamacoder.json`.
- **Scan time.** llamacoder took 229s before the flow-analysis fix in
  `035c6449` (227s of it in the flow stage, rebuilding values that were already
  equal); it now scans in about 5s. No other repository's timings or results
  changed, which is what makes the fix a speedup rather than a behaviour change.
- llamacoder's two scenarios exclude `preview-kits/`, a directory of template
  sources for generated previews whose `@/…` imports do not resolve in the host
  tsconfig. Without that exclusion both verdicts are `unknown`: an unresolved
  import anywhere in the repository could hide a provider call. That is the
  same conservatism that keeps `cb-command-model` unknown, and scoping the scan
  is the intended remedy.
- The missed and flagged call sites are unchanged from the previous run:
  `@google/generative-ai` and the OpenAI Agents SDK have no recognizer (the
  Google SDK binds its model when the client makes a model object, which the
  recognizer model cannot carry yet), and the `nextjs-ollama-llm-ui` tags
  fetch carries no tracked data and no host that identifies it.
- Unknown volume in zero-configuration scans is still high (2,778 records in
  chatbot-ui, 1,931 in llamacoder); the AI-related counts beside them are what
  `anvilmark scan show --section unknowns` and `anvilmark inventory` show.
