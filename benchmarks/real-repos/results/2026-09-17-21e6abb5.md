## Notes

- Compared with the baseline on `04a3555`: detection 22/60 → 56/60, provider
  identity 6/10 → 43/43, and the original eleven scenarios 3/11 → 11/11. Two
  false fails were removed; there were no false passes before or after.
- One label was widened before this run: in `cb-chat-openai-only`, the
  Anthropic route is also valid failure evidence (see the commit history).
- Five scenarios are **held out**: their expectations were written from the
  code before they were first run. On that first run (at the scanner changes
  in `2135df0d`, before the import refinements), four were correct. The miss
  was `cb-command-model` (expected pass, got unknown). The import refinements
  that followed removed the `runtime_selected_import` of locale JSON files, but
  the verdict stays unknown: `db/index.ts` imports `./file-items`, which does
  not exist at this commit. Unknown is the conservative answer for a missing
  module, so the expectation was not changed and the miss is kept.
- The remaining missed call site (`nextjs-ollama-llm-ui` `src/app/api/tags/route.ts:7`)
  is a `fetch` to a URL built from `OLLAMA_URL` that carries no tracked data,
  so nothing identifies it as an AI call. `@google/generative-ai` and the
  OpenAI Agents SDK are flagged as unsupported, not recognized.
- Unknown volume is still high in zero-configuration scans (for example
  2,780 records in chatbot-ui). `anvilmark scan show --section unknowns` now
  lists only those about AI calls, declared data or imports, once per
  location; the artifact keeps every record.
