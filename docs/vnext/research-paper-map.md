# Research paper map for ANVILMARK

Reviewed: 2026-10-07. This is a reading and experiment plan, not a claim that ANVILMARK improves on these papers today. **For the newer 2025–2026 literature, start with the [recent-paper update](research-paper-map-2026.md).** The current product boundary is in [`ANVILMARK-CANONICAL-BRIEF.md`](../../ANVILMARK-CANONICAL-BRIEF.md); the implemented conformance limits are in [`packages/conformance/README.md`](../../packages/conformance/README.md).

## Read first: closest to the core product

| Paper | What to take from it | ANVILMARK experiment or extension |
| --- | --- | --- |
| [Software Reflexion Models: Bridging the Gap Between Source and High-Level Models](https://www.cs.ubc.ca/~murphy/papers/rm/fse95.html) (Murphy, Notkin, Sullivan, FSE 1995) | Compare a declared architecture with source facts through explicit mappings; report agreement and disagreement. | Add a review view that shows *declared, observed, divergent, and unmapped* edges, with a source location and mapping provenance for each observed edge. Compare mapping effort and reviewer accuracy with the current conformance report. |
| [Checking Security Compliance between Models and Code](https://link.springer.com/article/10.1007/s10270-022-00991-5) (Tuma et al., *Software and Systems Modeling*, 2022) | Connect a security data-flow design to code through user-reviewed mappings and report convergence, divergence, and absence. Their implementation and experiments concern Java. | Test whether ANVILMARK's explicit source/sink/sanitizer declarations plus bounded TypeScript analysis reduce mapping work while retaining honest `unknown` outcomes. Evaluate on annotated TypeScript repos; compare false positives, missed violations, unmapped paths, and review time. |
| [Evaluation Cards: An Interpretive Layer for AI Evaluation Reporting](https://arxiv.org/abs/2606.09809) (Ghosh et al., arXiv preprint, 2026) | Combine benchmark, run, and model metadata; expose reproducibility, provenance, risk, and score comparability. This is unusually close to ANVILMARK's evidence layer. | Generate a decision evidence card from the existing contract: exact workload/candidate/config/dataset identities, source and freshness, unsupported comparisons, evidence gaps, and the approval it supports. Test whether reviewers catch intentionally mismatched model versions or datasets more often than with the current evidence view. Do not claim novelty for evidence cards alone. |
| [Holistic Evaluation of Language Models](https://openreview.net/forum?id=iO4LZibEqW) (Liang et al., TMLR 2023) | Evaluate multiple scenarios and metrics under documented conditions; make gaps visible. | For Atlas, compare candidates separately for redaction, classification, extraction, retrieval, and drafting. Record quality, latency, cost, privacy constraints, and missing measurements in one comparable matrix. Prevent an aggregate score from hiding a failed hard gate. |
| [Adding Error Bars to Evals: A Statistical Approach to Language Model Evaluations](https://arxiv.org/abs/2411.00640) (Miller, arXiv preprint, 2024) | Treat evaluation scores and differences as estimates with sampling uncertainty; plan sample sizes and paired comparisons. | Add confidence intervals and paired candidate differences for Atlas's held-out rows. Refuse a confident recommendation when the sample cannot distinguish candidates at the required threshold. Keep this separate from implementation conformance. The [historical research audit](../research/reset-2026/08-adversarial-verification.md) already warns against assuming a cited `evalci` package is available. |

## Read for workload-specific and decision improvements

| Paper | What to take from it | ANVILMARK experiment or extension |
| --- | --- | --- |
| [ARES: An Automated Evaluation Framework for Retrieval-Augmented Generation Systems](https://aclanthology.org/2024.naacl-long.20/) (Saad-Falcon et al., NAACL 2024) | Assess retrieval relevance, answer faithfulness, and answer relevance; calibrate automated judges with a small human-labeled set. | Split Atlas retrieval and drafting evidence into separate metrics. Compare automated citation/faithfulness judgments with blinded human judgments on the held-out tickets, including language slices. Keep judge scores below a human-reviewed quality gate until calibration is demonstrated. |
| [Model Cards for Model Reporting](https://arxiv.org/abs/1810.03993) (Mitchell et al., FAccT 2019) and [Datasheets for Datasets](https://www.microsoft.com/en-us/research/publication/datasheets-for-datasets/) (Gebru et al., CACM 2021) | Document intended use, limitations, evaluation conditions, and dataset collection/composition. | Require a compact dataset record for the 500 Atlas tickets: source, consent/privacy handling, language and class counts, split method, labeling process, and known gaps. Show candidate results by language and ticket type before approval. |
| [FrugalGPT: How to Use Large Language Models While Reducing Cost and Improving Performance](https://mlanthology.org/tmlr/2024/chen2024tmlr-frugalgpt/) (Chen, Zaharia, Zou, TMLR 2024) | Quality and cost vary by task and query; optimization needs measured tradeoffs. The paper studies adaptive model selection, which ANVILMARK does not currently execute. | Use its cost-quality framing for *design-time* candidate comparison. Produce a Pareto view constrained by Atlas quality, latency, privacy, and hardware gates. Compare projected cost with measured cost when runtime evidence is available. Avoid importing routing into the product boundary without a separate decision. |

## A credible research claim would need

1. **A fixed benchmark:** several real TypeScript/JavaScript repositories with independently labeled provider calls, data flows, sanitizer behavior, architecture mappings, and deliberate violations. Keep Atlas as one fixture, not the whole evaluation.
2. **Baselines:** current ANVILMARK, a simple declaration-and-grep baseline, and an established static analysis or architecture checking approach where a fair comparison is feasible. Report setup time as well as detection quality.
3. **Measurements:** violation precision/recall, `unknown` rate, mapping/review time, coverage by language and SDK, and time to explain a finding. For candidate recommendations: paired quality difference with uncertainty, latency distribution, estimated versus observed cost, and unsupported comparisons.
4. **Ablations:** remove explicit mappings, freshness checks, uncertainty, or human calibration one at a time to see which parts actually improve decisions. Report failures and cases outside supported analysis.

**Near-term implementation order:** start with a traceable declared-versus-observed view and a scored evidence-comparability report. Both use the existing contract and scan artifacts. Build the evaluation harness before claiming an advance over prior research.
