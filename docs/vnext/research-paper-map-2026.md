# Recent research for ANVILMARK (2025–2026)

Checked: 2026-10-07. This updates the [foundational paper map](research-paper-map.md) with recent work. **Published** means a proceedings/journal version was verified; **preprint** means no peer-reviewed version was established in this search. Paper results describe the authors' evaluated setting, not a result already achieved by ANVILMARK.

The most relevant gaps in the current project are the bounded TypeScript/JavaScript scanner and its explicit `unknown` verdicts ([scope](../../packages/conformance/README.md)), evidence comparison and freshness ([adapters](../../packages/adapters/README.md)), and hardware-fit estimates versus measured throughput ([scope](../../packages/hardware-sizing/README.md)).

## Closest architecture and conformance work

| Paper and status | Finding or method | Experiment for ANVILMARK |
| --- | --- | --- |
| [Evaluating Large Language Models for Detecting Architectural Decision Violations](https://arxiv.org/abs/2602.07609), ICSA 2026 | Studies 980 ADRs across 109 repositories; explicit code-inferable decisions were easier to verify than implicit or deployment decisions. | Label each contract rule by what evidence could establish it: code, declared runtime state, observed runtime state, or unavailable. Compare deterministic verdicts and LLM suggestions with blinded human labels, including abstention and explanation accuracy. |
| [R2Code: A Self-Reflective LLM Framework for Requirements-to-Code Traceability](https://arxiv.org/abs/2604.22432), COMPSAC 2026 | Uses decomposed requirement-to-code links, retrieval and consistency checking. | Compare its link-recovery approach with ANVILMARK's explicit component/file mappings on a held-out set. Measure link precision/recall, reviewer correction time, and whether a bad link changes a conformance verdict. |
| [CIAO: Code In Architecture Out](https://arxiv.org/abs/2604.08293), ICSA 2026 | Generates system-level architecture documents from repositories; 22 contributing developers reviewed its outputs, with weaker diagram and deployment results. | Compare a code-derived architecture suggestion against ANVILMARK's approved graph. Preserve each suggested node/edge's source evidence and `unknown` state, then measure whether reviewers find real drift faster. |
| [ArchBench: Benchmarking Generative-AI for Software Architecture Tasks](https://arxiv.org/abs/2603.17833), ICSA 2026 Companion showcase | Provides a task-plugin benchmark platform with trajectories and results. Its paper notes that some architecture tasks were still awaiting automated CLI evaluation and that text overlap/functional tests miss aspects of architecture quality. | Add a *contract violation detection* task with independently labeled call sites, mappings, and coverage gaps. Report precision, recall, abstention, explanation correctness, and setup effort, with a simple baseline. |
| [Beyond Correctness: Enhancing Architectural Reasoning in Code LLMs](https://arxiv.org/abs/2606.14948), Jun 2026 **preprint** | Uses source-grounded rubrics and an LLM judge to rate whether patches follow repository architecture. Its functional results use tests; the reported architecture-quality result relies on its own judge. | Freeze contract-derived rubrics before inspecting patches. Compare that judge, ANVILMARK's deterministic checks and blinded expert labels on held-out patches; measure violation detection separately from functional success. |
| [CloudFlow: Identifying Security-sensitive Data Flows in Serverless Applications](https://www.usenix.org/conference/usenixsecurity25/presentation/raffa), USENIX Security 2025 | Combines infrastructure definitions with static code analysis to find flows across serverless services. | Use a small multi-service Atlas variant to test whether source-only scanning misses a privacy violation visible in deployment/event bindings. Report the exact extra declaration or runtime evidence needed. This is a coverage test, not a commitment to support every cloud. |

## Evidence, evaluation and source attribution

| Paper and status | Finding or method | Experiment for ANVILMARK |
| --- | --- | --- |
| [ReproEvalCard: A Reporting Standard for Reproducible Evaluation of LLM Pipelines](https://aclanthology.org/2026.acl-short.22/), ACL 2026 | Specifies prompts, judge configuration, retrieval snapshots and intermediate traces needed to reproduce pipeline evaluations. An audit of 55 papers found frequent missing controls and traces. | Export a replay manifest alongside each promptfoo/Atlas result. Ask an independent reviewer to reconstruct the score, and distinguish missing artifact, changed artifact and genuine result drift. |
| [GenProve: Learning to Generate Text with Fine-Grained Provenance](https://aclanthology.org/2026.acl-long.228/), ACL 2026 | Represents sentence-level support as quotation, compression or inference; inference support remains harder to verify. | For each generated recommendation claim, attach an evidence span and support type. Test reviewer time and error rate on deliberately unsupported cost, latency and privacy claims. |
| [CiteGuard: Faithful Citation Attribution for LLMs via Retrieval-Augmented Validation](https://aclanthology.org/2026.acl-long.282/), ACL 2026 | Checks whether a cited source actually supports a claim, rather than merely whether a citation is present. | Seed Atlas response drafts and decision rationales with plausible but wrong citations. Compare a source-aware checker with a citation-presence baseline and human adjudication. |
| [The Consistency Dilemma in LLMs](https://proceedings.mlr.press/v306/mancoridis26a.html), ICML 2026 | Generator/evaluator agreement varies and can coexist with mistakes; self-consistency is not correctness. | Keep human labels independent of the model that proposed a candidate or judged its output. Measure agreement with blinded reviewers and repeated judge variance before treating an LLM score as decision evidence. |

## Newest preprints and decision economics

| Paper and status | Finding or method | Experiment for ANVILMARK |

| [Routing Should Pay for Itself: Sparse Supervision for Economical LLM Routing](https://arxiv.org/abs/2609.37402), 29 Sep 2026 **preprint** | Counts the up-front cost of acquiring evaluation feedback as well as later serving savings. The implementation is a runtime router, outside ANVILMARK's current role. | For design-time comparison, calculate the cost of the *next measurement* and its possible decision value. Show the volume at which a more expensive evaluation could pay back, with assumptions and uncertainty visible. |
| [Live Architecture Models for Cloud-Native Architecture-as-Code](https://arxiv.org/abs/2609.36148), 28 Sep 2026 **preprint** | Connects editable Kubernetes architecture intent to selected runtime facts and recurring read-only conformance checks. Keep absent or unsupported resources explicitly unknown. |
| [How Reproducible Are Evaluation Conclusions?](https://arxiv.org/abs/2609.30074), 24 Sep 2026 **preprint** | A self-audit shows that stable rankings can still be inaccurate and that retired model endpoints make old comparisons hard to rerun. | Show ranking stability, per-cell provenance and measurement date for Atlas candidate tables; mark retired or changed endpoints and never treat repeated agreement as correctness. |
| [Calibrate, Then Route](https://arxiv.org/abs/2609.16206), 14 Sep 2026 **preprint** | Hardware calibration changes serving predictions; gains in the reported system disappear in a small pool where simpler decisions suffice. The router itself is outside ANVILMARK scope. | Compare ANVILMARK's estimated local latency/throughput against a measured run on the named device and workload. Record conditions, residual error and when a static estimate is insufficient. |
| [HW-Router: Hardware-Aware Routing for Scalable Multi-LLM Serving](https://arxiv.org/abs/2608.14575), DAC 2026 | Shows that GPU type, queue, KV-cache pressure and recent token timing matter for serving latency. | Extend hardware evidence with measured load and prefill/decode timing *only when available*; avoid promoting VRAM-fit or idle benchmarks into p95 latency claims. |
| [LLMRouterBench](https://arxiv.org/abs/2601.07206), 12 Jan 2026 **preprint** | In a common evaluation, several sophisticated routers failed to reliably beat a simple baseline. | Compare any future candidate-ranking heuristic against a simple quality-gated cheapest-eligible baseline and an oracle on held-out Atlas-like workloads. Report regret and coverage, not just an example where a complex method wins. |

## Research direction and next tests

The papers make two proposed contributions hard to claim as new on their own: **evidence cards** and **architecture-versus-code checks**. A possible ANVILMARK contribution is a *single durable, user-approved decision record* whose claims link to source evidence and whose repository and optional runtime checks show precisely what was verified, what failed, and what remains unknown. That is a hypothesis requiring evaluation, not a novelty claim.

1. **Conformance benchmark:** use independently labeled real repositories and a multi-service Atlas variant. Compare current ANVILMARK, a simple rule baseline, and an LLM-assisted reviewer. Measure violation precision/recall, abstention, source-evidence correctness and review time. Separate code-observable rules from deployment-dependent rules.
2. **Evidence replay:** archive the exact prompt, dataset, candidate, judge, retrieval snapshot and tool version for an Atlas run. Ask someone who did not create the record to replay it, then deliberately change one dependency and verify that ANVILMARK explains the change.
3. **Measured decision calibration:** run the same workload on named local hardware, compare predicted and observed throughput/latency/cost, and report error and conditions. Compare model recommendations with a simple quality-gated baseline.

Keep preprint ideas provisional until independent reproduction or peer review. Any claim of improvement should use frozen labels and baselines, report failed cases and unsupported scope, and distinguish author-reported results from ANVILMARK measurements.
