## Architecture choice and evidence gate

The present local system uses explicit eligibility rules for hard restrictions, a source-scoped catalog, a task and architecture profile, exact run provenance, and a review record. These are engineering choices to make claims inspectable. The papers motivate measuring repository-level outcomes and cost, but **do not prove this implementation improves quality or saves users money**. Source provenance standards also describe records rather than establish outcome performance.

Build the decision system in this order:

1. Freeze representative tasks, checks, a repository snapshot, and a review rubric before seeing model outcomes. Keep architecture, implementation, test, and review tasks distinguishable.
2. Run the eligible candidates on matched tasks and account for retries, prompt preparation, handoff time, agent time, and billing mode. A subscription run may measure token allowance but has no known marginal cash cost.
3. Compare four policies where available: fixed cheap eligible model; fixed strong eligible model; cheap model with a verified repository handoff; selector using the same handoff. Randomized or matched assignment is needed to attribute a difference to selection rather than task mix.
4. Only after enough independent, human-reviewed examples exist should Anvilmark fit or calibrate a learned success estimate. Evaluate on held-out repositories and later model revisions, with uncertainty intervals and a predefined acceptance threshold.

The current test approver may exercise mechanics and identify failures. Its decisions must remain labeled as agent test evidence and excluded from human-reviewed model rankings.
